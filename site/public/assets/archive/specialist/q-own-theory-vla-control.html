VLA、世界模型与低层控制器怎样分工并对齐频率？

专项资料归档：机器人动作控制。后端与 Agent 面试主线不展开此专项，完整内容保留供按需查阅。

本质分别负责动作选择、未来预测和反馈执行；动作坐标、时间与安全合同不能被自然语言计划替代。

24. VLA 和世界模型、低层控制器怎么分工？

常见问法： VLA 输入输出是什么？是不是把 VLM 最后一层改成动作就够了？世界模型能直接控制机器人吗？

VLA 把视觉、语言与机器人状态映射为动作，但动作的表示、时间尺度和安全执行层必须明确，不能只把自然语言计划当作可执行控制。

输入可能包括多相机画面、语言指令、关节状态和历史观察；输出可能是离散动作 token、末端位姿增量、关节目标或一段连续动作。不同机器人自由度、坐标系、夹爪定义与控制周期不同，不能把相同维度的数组直接跨设备发送。

离散动作适合接入 token 预测，但量化精度与序列长度是取舍；连续动作头可以直接回归，或通过 diffusion/flow 建模多种可行轨迹。动作分块一次生成未来一段动作，减少频繁大模型推理，但执行太长会降低对环境变化的响应。

可以沿一次执行讲三者分工：世界模型预测候选动作之后环境可能怎样变化，可以帮助规划与评估；VLA 策略选择动作；低层控制器再按控制周期跟踪目标、限幅并处理反馈。三者可以结合，但“预测会发生什么”“选择做什么”和“把动作执行稳”承担的是不同责任。

3 Hz 模型能配 50 Hz 控制器吗？ 可以通过动作分块与分层系统衔接，但不能说模型已经达到 50 Hz 闭环推理。模型约每 333 ms 更新一次计划，控制器约每 20 ms 消费一个控制目标；中间发生的突变需要低层反馈、安全层或更快重规划处理。要分别报告推理频率、动作输出频率和反馈响应延迟。

遥操作数据怎样采？微调需要多少？ 操作者通过主从机械臂、手柄或其他控制接口给目标动作，系统同步记录相机、状态、控制指令与执行结果。必须校准时钟、坐标与延迟，并区分发出的命令和实际达到的状态。数据量没有通用固定答案，受任务变化、已有模型能力、成功轨迹多样性和控制精度影响；用逐步增加数据的学习曲线决定是否继续采集，比背一个轨迹数量更可靠。子任务标注要写清开始条件、成功/失败终止、重叠和中断规则，保留整段任务与子段关系，避免只挑成功片段造成评测偏差。

真实机器人怎么保证安全？ 限制工作空间、速度、力和关节范围，检查观测是否过期，保留急停与人工接管，先仿真和受控测试再逐步扩大范围。模型置信度或语言承诺不能替代这些约束。
