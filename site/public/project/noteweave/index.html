01可恢复的 Deep Research Agent

简历原文设计验证驱动、可恢复的 Deep Research Agent：针对开放研究易漂移、证据不足和长任务中断的问题，将研究过程抽象为 Table-as-State ，显式维护研究对象、待验证字段、Evidence 与结论，通过 Plan / Replan、Verifier 和受限反证持续纠偏；结合 Checkpoint 与引用审计支持任务断点恢复和结论逐项回溯。离线评测中，有效研究单元完成率由 67% 提升至 83%。
简历里的说法对应机制本节位置
Table-as-State研究表：行 = 研究对象，列 = 待验证字段，格 = 研究单元；上限 20 行 × 8 列、80 格研究账本
研究对象、待验证字段、Evidence 与结论每格独立保存候选值、证据卡（支持 / 反驳关系）、判定状态和结论研究账本
Plan / Replan八个阶段的计划视图；Replan 只针对缺口格，每次最多 3 条新查询阶段与纠偏
Verifier局部验证（单格，规则短路 → 模型）与全局验证（覆盖与完成契约）两层验证
受限反证反证查询族预算 1；冲突在预算内未解决 → 转人工，而不是无限追查阶段与纠偏
Checkpoint每波子任务结束写检查点；接管从检查点继续，只重新领取未验证的格租约与恢复
引用审计报告逐条结论核对引文窗口、归属、数字日期和否定极性，最多修订 2 轮两层验证
任务断点恢复数据库租约 60 秒 + 15 秒心跳，接管代际加一，旧回执 fencing 拒绝租约与恢复
结论逐项回溯报告每条结论 → 证据卡 → 读取窗口 → 原文位置两层验证

开放式研究容易漂移、证据不足时编结论、中断后只能整段重来。把研究状态收成一张表，状态中心是“格子”，而不是一段越写越长的笔记：执行按格派发、验证按格进行，失败只对缺口格局部重规划。Host 是权威状态的唯一写者，Worker 无状态，只做检索与抽取、交回候选。

租约、fencing 与检查点恢复

回执校验防的是什么

研究要能量化完成率、能中断后续跑、能拒绝晚到写回，这三件事都要求状态是可查询的格子。放弃的是开放网页上的浏览深度，这一点不与产品级 Deep Research 比。叙事题为主时加重文章化路径，等待人工成为耗时大头时再引入工作流引擎管等待，格子账本仍留在库里。

03Kafka 异步资料处理流水线

简历原文搭建异步资料处理流水线：针对大文件同步解析阻塞请求、资料处理链路耗时较长的问题，将解析、切片、向量化和索引构建拆分为 Kafka 异步任务，并通过任务幂等与失败恢复保障长链路可靠执行，支持 128 MB 单文件异步接入，避免大文件处理占用业务请求链路。
简历里的说法对应机制本节位置
大文件同步解析阻塞请求上传接口只落资料版本和 Outbox 就返回，处理全部异步端到端流程
解析、切片、向量化和索引构建四个阶段四个 topic：source.parse / chunk / embed / index；快照记录 processing_stage端到端流程
Kafka 异步任务Outbox 派发器带租约发送；阶段之间只传资料快照 IDOutbox 派发
任务幂等按“资料快照 ID + 阶段”去重；向量批次唯一键 = 快照 + 批次版本 + 批次号幂等与恢复
失败恢复派发 5 次退避后死信；消费 2 次重试后 .DLT；向量批次租约过期可重领；索引失败按退避自动重试幂等与恢复
128 MB 单文件异步接入单文件上传的配置上限，分片上传后进入流水线端到端流程

大文件同步处理会阻塞请求，长链路失败难定位。上传后的处理拆成解析、切片、向量化、索引四个阶段，每个阶段独立扩消费者；索引是可重建的投影。

方案怎么做在哪出问题代价结论

05Context 与长期 Memory

简历原文设计 Context 与长期 Memory 机制：针对长会话全量回放导致 Token 膨胀、自动记忆容易污染后续事实的问题，采用 Topic-aware Window + 增量摘要 压缩长会话上下文，通过候选提取与门控晋升沉淀长期 Memory，并将用户偏好与资料 Evidence 分层隔离。相比全量历史回放，平均输入 Token 降低 34%，关键事实检查通过率 92%。
简历里的说法对应机制本节位置
Topic-aware Window按话题切分会话：词项覆盖度 + 向量余弦各占一半；当前话题保留原文尾部 2–8 条消息话题切分与窗口
增量摘要窗口以外的内容由该话题的增量摘要覆盖；摘要与窗口共用一条边界，最多滞后 8 条话题切分与窗口
候选提取对话与产物反馈中抽出的只是候选，归入语义槽位Memory 门控
门控晋升Beta 后验均值 ≥ 0.70、方差 ≤ 0.04、效用 ≥ 0.60、风险 < 0.70 四道门；否则待确认Memory 门控
用户偏好与资料 Evidence 分层隔离Memory 只控制语气、结构和要避免的写法；事实与引用只来自资料证据分层注入
平均输入 Token 降低 34%、关键事实检查通过率 92%同一批长会话离线回放，两项一起看指标口径

全量回放的 Token 随轮次线性上涨，旧话题还会串进当前回答；固定最近 N 轮又会把早先的约束过早丢掉。自动抽取的记忆可能是误判，一旦生效就会长期污染回答。所以上下文按话题压缩，记忆按门控晋升，并且记忆和事实分层。

话题切分与窗口

Memory 门控

风险分项取值
类别基础分禁止写法 0.28 · 术语 0.18 · 结构 0.14 · 交互 0.12 · 其他 0.10
作用范围整个工作区 +0.16 · 更窄范围 +0.06
冲突同语义槽位存在不同取值，或冲突检查没跑成：+0.55（直接越过 0.70 风险门）

冲突不靠正反关键词，而是把记忆归到语义槽位（如“输出格式”），同槽位不同取值就算冲突。冲突检查没跑成也按有冲突计——宁可多进待确认，也不让一条未检查的记忆自动生效。

分层注入：偏好与证据隔离

层来源能影响什么不能影响什么
用户偏好（Memory）门控晋升后的记忆语气、结构、术语、要避免的写法事实、数字、结论和引用
资料证据（Evidence）QA / Note / Wiki 检索链路回答里的事实与引用—
会话上下文话题窗口 + 增量摘要当前任务的约束与上下文长期偏好（不从会话直接写入）

方案对比

方案怎么做在哪出问题代价结论
全量回放历史消息全部拼进 PromptToken 线性涨；论文 A 的数据集名被带进论文 B 的回答长会话不可持续只适合短会话
固定最近 N 轮只保留尾部若干轮原文开头约定（如“全部用英文术语”）滑出窗口后被遗忘用“忘”换省钱不选
每次全量重摘要整个历史反复压成一条反复摘要漂移，细节丢失难控摘要成本高不选
话题窗口 + 增量摘要 采用当前话题留原文，关闭话题进摘要话题切错会丢历史；摘要可能压掉数字和限定语切分与摘要链路 + 关键事实回归检查采用

多话题长会话既要压 Token 又要留住后面还会用到的事实，所以 −34% 必须和 92% 一起看。跨会话引用很久以前的内容成为常态时，再加一层长期记忆检索；回放集上切分错误率升高时，把切分全面交给模型并接受更高成本。

方案对比

方案怎么做在哪出问题代价结论
抽到就写入模型抽出偏好立刻生效一次误判长期污染后续回答实现最简单不选
按来源给固定可信度每个来源一个固定分数分不清“说过一次”和“反复确认五次”；效用写入后从不更新简单可解释早期方案，已替换
Beta 后验 + 四道门 + 人工确认 采用均值管可信、方差管证据量，再加效用和风险；不过门进待确认先验与阈值是初始值，未经大样本校准要维护证据更新与槽位冲突采用
记忆参与事实回答把记忆当作可引用的知识事实被记忆污染，错误难以追溯到资料—不选：只控制表达

写错记忆的代价比少记一条更大，所以宁可多进待确认。偏好与资料证据分层后，记忆错了最多影响表达方式，不会改变答案里的事实与引用。

指标口径

简历数字定义（公式）不代表什么
−34%降幅 = 1 − Context 编译后平均每轮输入 Token ÷ 全量回放平均每轮输入 Token；同一批长会话离线回放，同一 Token 估算器，只算对话历史不含输出和摘要成本，不是线上省下的钱
92%关键事实检查通过率 = 压缩上下文下答对的关键事实检查数 ÷ 检查总数（数字、截止日期、限定条件等后续会用到的事实）；先关键词规则、再人工判定不是整体回答正确率
