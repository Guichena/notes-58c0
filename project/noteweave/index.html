01整体架构

Agent 编排不用框架，由 Backend 状态机驱动；模型每一步只产出结构化 JSON。

02模块 ① 验证驱动的 Deep Research

解决：研究漂移、证据不足时编结论、中断后只能重来。

机制作用
Table-as-State研究状态落在表里，可审计、可恢复
Verifier先比对原文片段与数字日期，再判蕴含
受限反证冲突保留双方，次数有上限
Checkpoint恢复时校验摘要，只重做缺口
引用审计结论逐项回溯到证据

03模块 ② 任务感知的问答 / 精读 / Wiki

解决：一条 RAG 无法同时满足查事实、读长文和跨资料整合。

模式适合检索方式证据形态
问答快速查事实BM25 + 向量 → RRF → Rerank零散片段
精读长文档连续阅读先定资料，再按原文顺序读连续窗口连续窗口
Wiki跨资料整合知识页 BM25F + 链接传播 + 图遍历知识页 + 来源回链

04模块 ③ Kafka 异步资料处理流水线

解决：大文件同步处理阻塞请求，长链路失败难定位、难恢复。

故障窗口手段
提交后任务没发出Outbox 同事务写入
重复消费阶段幂等键去重
某阶段反复失败死信 + 回写状态
索引暂时不可用自动退避重试
Worker 中途退出租约到期后重新领取

05模块 ④ Schema 驱动的产物生成框架

解决：每种产物各写一套 Prompt 和流程，难复用、难校验。

产物导出来源约束
报告 / 讲义PDF逐条引用资料证据
测验 / 面试问答页面逐条引用资料证据
学习 PPTPPTX逐条引用资料证据
视频摘要 / 知识博客页面 / PDF每个观点引用字幕原文

06模块 ⑤ Context 与长期 Memory

解决：长对话上下文膨胀；自动记忆可能把错误带进回答。

门控问的问题
来源可信度是用户明确说的吗
预期效用以后还会用到吗
风险写错了代价大吗
冲突和已有记忆矛盾吗

07关键设计取舍

问题备选选择理由代价
Agent 编排LangChain 等框架Backend 状态机状态需持久化、可审计、可恢复；每步可校验要自己写编排
语言分工全部 PythonJava 真源 + Python Worker判定、权限、版本集中一处，避免多写者竞态跨语言契约要维护
研究状态Agent 自维护 ScratchpadTable-as-State每格独立追踪，能局部修复、断点恢复表结构设计更复杂
任务投递提交后直接发 KafkaOutbox + Kafka任务与业务同事务，不丢任务多一层 Relay
检索存储独立向量库Elasticsearch 一库多用BM25 与向量一起混合召回，少一套组件向量能力不如专用库
融合方式按分数加权RRF 按名次不同召回的分数不可比，名次稳健丢失分数幅度信息
记忆作用参与事实回答只控制表达事实不被记忆污染，写错代价可控记忆能力受限
